Dokumen Arsitektur Implementasi

Disaster Intelligence Agent

Sistem agen yang mengubah dokumen dan laporan kebencanaan mentah — siaran pers BNPB/BMKG, laporan lapangan, berita — menjadi laporan situasi (situation report) terstruktur dan terverifikasi. LangGraph bertindak sebagai orchestrator state-machine, LlamaIndex Workflows sebagai mesin ekstraksi dokumen, dan lapisan resilience khusus menangani timeout serta halusinasi LLM.

LangGraph · orchestrator LlamaIndex Workflows · extractor Pydantic v2 · validasi skema Tenacity · retry & backoff Python 3.11+
TAHAP 01

Ingest

Dokumen masuk dari file, URL, atau feed; dinormalisasi menjadi teks + metadata sumber.

TAHAP 02

Ekstraksi

LlamaIndex Workflow mem-parsing dokumen dan mengekstrak entitas bencana ke skema Pydantic.

TAHAP 03

Verifikasi

Setiap klaim hasil ekstraksi dicek grounding-nya ke teks sumber; yang tak berdasar ditolak.

TAHAP 04

Laporan

State final dirender menjadi situation report JSON + ringkasan naratif siap distribusi.

01 — ARSITEKTUR SISTEM

Lima lapisan, dua framework, satu state

Pemisahan tanggung jawabnya tegas: LlamaIndex Workflows hanya mengurus document understanding — mengubah dokumen menjadi data terstruktur lewat workflow berbasis event. LangGraph mengurus control flow — urutan langkah, percabangan, loop perbaikan, dan checkpoint state. Keduanya berkomunikasi lewat satu kontrak: objek ExtractionResult Pydantic yang ditulis ke AgentState.

Kenapa LangGraph untuk orkestrasi?

  • Alur kebencanaan bersifat non-linear: ekstraksi bisa gagal, perlu loop perbaikan, dan kadang harus berhenti menunggu manusia — graph dengan conditional edge mengekspresikan ini lebih jujur daripada chain lurus.
  • State eksplisit + checkpointer membuat setiap run bisa di-resume, di-replay, dan diaudit — penting saat laporan dipakai untuk keputusan evakuasi.
  • interrupt() memberi jalur human-in-the-loop tanpa memutus proses.

Kenapa LlamaIndex Workflows untuk ekstraksi?

  • Reader bawaan menangani PDF/DOCX/teks dengan satu antarmuka; workflow berbasis event membuat langkah parsing → ekstraksi → validasi mudah diuji per step.
  • llm.as_structured_llm(Schema) memaksa output LLM mengikuti skema Pydantic — kegagalan skema terdeteksi sebagai exception, bukan teks bebas yang harus di-parse manual.
  • Workflow berjalan di dalam satu node LangGraph, jadi kompleksitas ekstraksi tidak bocor ke graph utama.

config.pySatu-satunya tempat ambang batas & kredensial dibaca
"""Konfigurasi terpusat Disaster Intelligence Agent.

Semua nilai dapat dioverride lewat environment variable berprefix DIA_,
mis. DIA_LLM_TIMEOUT_S=45. Tidak ada modul lain yang membaca os.environ.
"""
from functools import lru_cache

from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_prefix="DIA_")

    # --- LLM ---
    llm_primary: str = "gpt-4o"          # model utama ekstraksi & penilaian
    llm_fallback: str = "gpt-4o-mini"    # model cadangan bila primary gagal total
    llm_api_key: str = ""                # DIA_LLM_API_KEY
    llm_temperature: float = 0.0         # 0 = deterministik, kurangi variasi halusinasi

    # --- Resilience: timeout & retry ---
    llm_timeout_s: float = 30.0          # batas keras per panggilan LLM (asyncio.wait_for)
    llm_max_retries: int = 4             # percobaan ulang untuk error retryable
    retry_base_delay_s: float = 1.0      # backoff awal; digandakan tiap percobaan
    retry_max_delay_s: float = 30.0      # plafon backoff (jitter ditambahkan tenacity)

    # --- Loop perbaikan & verifikasi (routing LangGraph) ---
    max_repairs: int = 3                 # maks loop validate -> repair sebelum human review
    min_grounding_rate: float = 0.8      # < 80% klaim ter-grounding => human review
    min_confidence: float = 0.55         # confidence ekstraksi di bawah ini => repair


@lru_cache
def get_settings() -> Settings:
    """Singleton settings; lru_cache agar .env hanya dibaca sekali."""
    return Settings()
schemas.pyKontrak data Pydantic — dipakai LLM terstruktur, validator, dan output JSON
"""Skema data (Pydantic v2) — kontrak tunggal antar semua lapisan.

Prinsip anti-halusinasi tertanam di skema: setiap kelompok klaim faktual
WAJIB menyertakan evidence_quote, kutipan verbatim dari dokumen sumber.
Kutipan ini yang diverifikasi resilience.verify_grounding().
"""
from datetime import datetime
from enum import Enum
from typing import Literal

from pydantic import BaseModel, Field


class DisasterType(str, Enum):
    EARTHQUAKE = "earthquake"
    FLOOD = "flood"
    LANDSLIDE = "landslide"
    VOLCANO = "volcano"
    TSUNAMI = "tsunami"
    WILDFIRE = "wildfire"
    DROUGHT = "drought"
    STORM = "storm"
    OTHER = "other"


class SourceDocument(BaseModel):
    """Dokumen sumber yang sudah dinormalisasi oleh node ingest."""

    name: str
    url: str | None = None
    text: str
    content_hash: str                       # sha256 teks, untuk audit trail
    retrieved_at: datetime


class DisasterEvent(BaseModel):
    disaster_type: DisasterType
    title: str = Field(min_length=5)
    occurred_at: datetime | None = None
    province: str
    regency: str | None = None
    district: str | None = None
    latitude: float | None = Field(default=None, ge=-90, le=90)
    longitude: float | None = Field(default=None, ge=-180, le=180)


class CasualtyReport(BaseModel):
    deaths: int = Field(ge=0)
    injured: int = Field(ge=0)
    missing: int = Field(ge=0)
    displaced: int = Field(ge=0)
    evidence_quote: str = Field(
        description="Kutipan verbatim dari teks sumber yang mendukung "
                    "angka-angka korban di atas."
    )


class InfrastructureDamage(BaseModel):
    asset: str
    damage_level: Literal["light", "moderate", "heavy", "destroyed", "cut_off"]
    evidence_quote: str


class ExtractionResult(BaseModel):
    """Output LlamaIndex Workflow; ditulis ke AgentState['extraction']."""

    event: DisasterEvent
    casualties: CasualtyReport
    infrastructure_damage: list[InfrastructureDamage] = []
    evacuation_points: int | None = Field(default=None, ge=0)
    needs: list[str] = []
    extraction_confidence: float = Field(ge=0.0, le=1.0)
    extractor: Literal["llama_index_workflow", "rule_based_fallback"]
    model_used: Literal["primary", "fallback", "none"]


class EnrichmentData(BaseModel):
    latitude: float | None = None
    longitude: float | None = None
    admin_region: str | None = None
    weather_summary: str | None = None      # mis. dari API BMKG
    notes: list[str] = []


class ImpactAssessment(BaseModel):
    severity_level: Literal["low", "moderate", "high", "critical"]
    impact_score: int = Field(ge=0, le=100)
    affected_population_estimate: int = Field(ge=0)
    rationale: str


class ClaimCheck(BaseModel):
    claim: str
    grounded: bool
    quote_found: str | None = None


class GroundingReport(BaseModel):
    checks: list[ClaimCheck]
    total_claims: int
    grounded_claims: int

    @property
    def grounding_rate(self) -> float:
        return self.grounded_claims / self.total_claims if self.total_claims else 0.0

    @property
    def ungrounded(self) -> list[str]:
        return [c.claim for c in self.checks if not c.grounded]


class SituationReport(BaseModel):
    """Output final graph — kontrak JSON untuk konsumen hilir."""

    report_id: str
    run_id: str
    generated_at: datetime
    status: Literal["verified", "needs_review", "fallback_extraction"]
    headline: str
    event: DisasterEvent
    casualties: CasualtyReport
    impact: ImpactAssessment
    grounding: GroundingReport
    recommended_actions: list[str]
    sources: list[SourceDocument]
    narrative_summary: str
state.pyAgentState — TypedDict yang dibawa ke seluruh graph
"""State LangGraph: satu TypedDict yang dibaca/ditulis semua node.

- Field biasa: last-write-wins (node terakhir menentukan nilai).
- Field 'errors': reducer operator.add agar log error terakumulasi,
  tidak pernah ditimpa node lain — penting untuk audit kegagalan.
- Semua keputusan conditional edge HARUS bisa diambil dari state ini.
"""
import operator
from typing import Annotated, Literal, TypedDict

from schemas import (
    EnrichmentData,
    ExtractionResult,
    GroundingReport,
    ImpactAssessment,
    SituationReport,
    SourceDocument,
)

Status = Literal[
    "ingested", "extracted", "validated", "enriched",
    "assessed", "verified", "reported",
    "needs_review", "failed",
]


class AgentState(TypedDict):
    # Input
    run_id: str
    raw_sources: list[str]                       # path / URL / teks mentah

    # Tahap ingest & ekstraksi
    documents: list[SourceDocument]
    extraction: ExtractionResult | None

    # Kontrol loop perbaikan (validate <-> repair)
    validation_errors: list[str]                 # diumpankan ke prompt repair
    repair_count: int

    # Observabilitas panggilan LLM
    llm_attempts: int                            # termasuk retry timeout

    # Tahap pengayaan & penilaian
    enrichment: EnrichmentData | None
    assessment: ImpactAssessment | None

    # Verifikasi anti-halusinasi
    grounding: GroundingReport | None
    needs_human_review: bool

    # Output
    report: SituationReport | None

    # Akumulasi error (reducer: append, bukan replace)
    errors: Annotated[list[str], operator.add]
    status: Status


def initial_state(run_id: str, raw_sources: list[str]) -> AgentState:
    """State awal yang konsisten — selalu buat state lewat fungsi ini."""
    return AgentState(
        run_id=run_id,
        raw_sources=raw_sources,
        documents=[],
        extraction=None,
        validation_errors=[],
        repair_count=0,
        llm_attempts=0,
        enrichment=None,
        assessment=None,
        grounding=None,
        needs_human_review=False,
        report=None,
        errors=[],
        status="ingested",
    )
resilience.pyInti pertahanan: retry timeout/rate-limit + verifikasi grounding anti-halusinasi
"""Lapisan resilience: dua musuh, dua pertahanan.

1) KEGAGALAN TRANSIEN (timeout, rate-limit, koneksi putus)
   - asyncio.wait_for memberi batas keras per panggilan.
   - Tenacity mengulang HANYA error retryable, dengan exponential
     backoff + jitter agar tidak menabrak rate-limit secara serempak.
   - Error non-retryable (auth, request tidak valid) langsung dilempar:
     mengulanginya hanya membuang waktu & biaya.

2) HALUSINASI (output valid secara skema, tapi tidak berdasar)
   - Skema saja tidak cukup. verify_grounding() memeriksa bahwa setiap
     evidence_quote BENAR-BENAR ADA di teks sumber, dan angka korban
     yang diklaim muncul di dalam kutipannya.
   - Klaim yang lolos skema tapi gagal grounding tidak diteruskan:
     graph mengarahkannya ke human review (lihat nodes.route_after_verify).
"""
import asyncio
import logging
import re
import unicodedata
from collections.abc import Awaitable, Callable
from typing import TypeVar

from openai import (
    APIConnectionError,
    APITimeoutError,
    InternalServerError,
    RateLimitError,
)
from tenacity import (
    AsyncRetrying,
    before_sleep_log,
    retry_if_exception_type,
    stop_after_attempt,
    wait_exponential_jitter,
)

from config import Settings
from schemas import ExtractionResult, GroundingReport, ClaimCheck, SourceDocument

logger = logging.getLogger("disaster_intel.resilience")

T = TypeVar("T")

# Error yang layak dicoba lagi. Perhatikan: AuthenticationError dan
# BadRequestError SENGAJA tidak ada di sini — retry tidak akan menolong.
RETRYABLE_LLM_ERRORS = (
    APITimeoutError,
    APIConnectionError,
    RateLimitError,
    InternalServerError,
    asyncio.TimeoutError,   # dari wait_for di bawah
)


async def call_llm_resilient(
    factory: Callable[[], Awaitable[T]],
    *,
    settings: Settings,
    on_attempt: Callable[[], None] | None = None,
) -> T:
    """Jalankan satu panggilan LLM dengan timeout keras + retry backoff.

    `factory` adalah coroutine factory (bukan coroutine) agar setiap
    percobaan membuat panggilan BARU, bukan mengulang awaitable yang sama.
    `on_attempt` dipakai node untuk menaikkan state['llm_attempts'].
    """
    retrying = AsyncRetrying(
        stop=stop_after_attempt(settings.llm_max_retries),
        wait=wait_exponential_jitter(
            initial=settings.retry_base_delay_s,
            max=settings.retry_max_delay_s,
        ),
        retry=retry_if_exception_type(RETRYABLE_LLM_ERRORS),
        before_sleep=before_sleep_log(logger, logging.WARNING),
        reraise=True,   # setelah percobaan habis, exception asli diteruskan
    )
    async for attempt in retrying:
        with attempt:
            if on_attempt is not None:
                on_attempt()
            return await asyncio.wait_for(
                factory(),
                timeout=settings.llm_timeout_s,
            )
    raise RuntimeError("unreachable: AsyncRetrying selalu return atau raise")


# ---------------------------------------------------------------------------
# Verifikasi grounding (anti-halusinasi)
# ---------------------------------------------------------------------------

def _normalize(text: str) -> str:
    """Samakan bentuk teks: huruf kecil, tanpa diakritik, spasi tunggal,
    dan pemisah ribuan angka dibuang ("1.240" -> "1240")."""
    text = unicodedata.normalize("NFKD", text.lower())
    text = "".join(c for c in text if not unicodedata.combining(c))
    text = re.sub(r"(\d)\.(\d{3}\b)", r"\1\2", text)   # ribuan gaya id-ID
    text = re.sub(r"\s+", " ", text)
    return text.strip()


def _quote_in_source(quote: str, corpus: str) -> bool:
    return _normalize(quote) in corpus


def _numbers_in(text: str) -> set[int]:
    return {int(n) for n in re.findall(r"\d[\d.]*", _normalize(text))}


def verify_grounding(
    extraction: ExtractionResult,
    documents: list[SourceDocument],
) -> GroundingReport:
    """Periksa setiap klaim faktual ekstraksi terhadap teks sumber.

    Sebuah klaim dinyatakan ter-grounding bila:
    1. evidence_quote-nya ditemukan verbatim (setelah normalisasi)
       di salah satu dokumen sumber, DAN
    2. khusus angka korban: angka yang diklaim benar-benar muncul
       di dalam kutipan tersebut (mencegah kutipan asli dipakai
       untuk menopang angka karangan).
    """
    corpus = _normalize(" \n ".join(doc.text for doc in documents))
    checks: list[ClaimCheck] = []

    # Klaim angka korban
    cas = extraction.casualties
    claimed = {
        "deaths": cas.deaths, "injured": cas.injured,
        "missing": cas.missing, "displaced": cas.displaced,
    }
    quote_ok = _quote_in_source(cas.evidence_quote, corpus)
    quote_numbers = _numbers_in(cas.evidence_quote)
    for field, value in claimed.items():
        grounded = quote_ok and (value == 0 or value in quote_numbers)
        checks.append(ClaimCheck(
            claim=f"casualties.{field} = {value}",
            grounded=grounded,
            quote_found=cas.evidence_quote if grounded else None,
        ))

    # Klaim kerusakan infrastruktur
    for dmg in extraction.infrastructure_damage:
        grounded = _quote_in_source(dmg.evidence_quote, corpus)
        checks.append(ClaimCheck(
            claim=f"infrastructure: {dmg.asset} ({dmg.damage_level})",
            grounded=grounded,
            quote_found=dmg.evidence_quote if grounded else None,
        ))

    # Klaim jumlah titik pengungsian
    if extraction.evacuation_points is not None:
        grounded = extraction.evacuation_points in _numbers_in(
            " ".join(doc.text for doc in documents)
        )
        checks.append(ClaimCheck(
            claim=f"evacuation_points = {extraction.evacuation_points}",
            grounded=grounded,
        ))

    return GroundingReport(
        checks=checks,
        total_claims=len(checks),
        grounded_claims=sum(1 for c in checks if c.grounded),
    )
extractor/workflow.pyLlamaIndex Workflow: prepare → extract → validate, berjalan di dalam satu node LangGraph
"""Ekstraksi dokumen dengan LlamaIndex Workflows.

Workflow ini TIDAK tahu apa-apa tentang LangGraph. Ia menerima daftar
SourceDocument dan mengembalikan ExtractionResult — atau melempar
ExtractionFailed setelah strategi internalnya habis:

  percobaan 1..N : model primary, dibungkus call_llm_resilient()
  percobaan N+1  : model fallback (lebih murah/berbeda provider)
  tetap gagal    : raise ExtractionFailed -> node LangGraph beralih
                   ke fallback rule-based (fallback.py)

Mode repair: bila LangGraph mengirim validation_errors dari putaran
sebelumnya, error tersebut disisipkan ke prompt agar LLM memperbaiki
kesalahan spesifiknya, bukan mengulang dari nol.
"""
import hashlib
from datetime import datetime, timezone

from llama_index.core.workflow import Event, StartEvent, StopEvent, Workflow, step
from llama_index.llms.openai import OpenAI

from config import Settings
from resilience import call_llm_resilient
from schemas import ExtractionResult, SourceDocument

EXTRACTION_INSTRUCTION = """Anda adalah analis data kebencanaan.
Ekstrak informasi kejadian bencana dari dokumen berikut ke skema yang
diberikan. Aturan ketat:
- Hanya tulis fakta yang ADA di dokumen. Jangan mengarang angka.
- Untuk setiap kelompok klaim, isi evidence_quote dengan kutipan
  PERSIS dari dokumen (verbatim) yang mendukung klaim tersebut.
- Bila suatu angka tidak disebutkan, isi 0 (korban) atau null.
- extraction_confidence: nilai kejujuran Anda atas kelengkapan ekstraksi.
"""


class ExtractionFailed(RuntimeError):
    """Kedua model gagal menghasilkan ExtractionResult yang valid."""


class PreparedEvent(Event):
    combined_text: str
    feedback: str | None = None          # pesan error repair dari LangGraph


class ExtractedEvent(Event):
    result: ExtractionResult
    model_used: str


class ExtractionWorkflow(Workflow):
    def __init__(self, settings: Settings, **kwargs):
        super().__init__(**kwargs)
        self.settings = settings

    def _llm(self, model: str) -> OpenAI:
        return OpenAI(
            model=model,
            api_key=self.settings.llm_api_key,
            temperature=self.settings.llm_temperature,
            timeout=self.settings.llm_timeout_s,
        )

    @step
    async def prepare(self, ev: StartEvent) -> PreparedEvent:
        documents: list[SourceDocument] = ev.get("documents", [])
        combined = "\n\n--- DOKUMEN ---\n\n".join(
            f"[{doc.name}]\n{doc.text}" for doc in documents
        )
        return PreparedEvent(
            combined_text=combined,
            feedback=ev.get("feedback"),   # None pada putaran pertama
        )

    @step
    async def extract(self, ev: PreparedEvent) -> ExtractedEvent:
        prompt = EXTRACTION_INSTRUCTION
        if ev.feedback:
            prompt += (
                "\n\nPERBAIKI EKSTRAKSI SEBELUMNYA. Kesalahan validasi:\n"
                f"{ev.feedback}\nHasilkan ulang ekstraksi yang memperbaikinya."
            )
        prompt += f"\n\nDOKUMEN:\n{ev.combined_text}"

        last_error: Exception | None = None
        for model_name, label in (
            (self.settings.llm_primary, "primary"),
            (self.settings.llm_fallback, "fallback"),
        ):
            structured_llm = self._llm(model_name).as_structured_llm(ExtractionResult)
            try:
                result = await call_llm_resilient(
                    lambda: structured_llm.acomplete(prompt),
                    settings=self.settings,
                )
                parsed: ExtractionResult = result.raw  # sudah divalidasi Pydantic
                parsed = parsed.model_copy(update={
                    "extractor": "llama_index_workflow",
                    "model_used": label,
                })
                return ExtractedEvent(result=parsed, model_used=label)
            except Exception as exc:  # timeout habis, skema gagal, dsb.
                last_error = exc
                continue              # turun ke model berikutnya

        raise ExtractionFailed(f"Semua model gagal mengekstrak: {last_error}")

    @step
    async def validate(self, ev: ExtractedEvent) -> StopEvent:
        # Validasi kedua di sisi workflow: confidence terlalu rendah
        # dianggap ekstraksi tidak layak dan dilempar sebagai kegagalan
        # agar node LangGraph dapat memutuskan repair / fallback.
        if ev.result.extraction_confidence < self.settings.min_confidence:
            raise ExtractionFailed(
                f"Confidence {ev.result.extraction_confidence:.2f} di bawah "
                f"ambang {self.settings.min_confidence}"
            )
        return StopEvent(result=ev.result)


def hash_text(text: str) -> str:
    return "sha256:" + hashlib.sha256(text.encode("utf-8")).hexdigest()


def make_document(name: str, text: str, url: str | None = None) -> SourceDocument:
    return SourceDocument(
        name=name, url=url, text=text,
        content_hash=hash_text(text),
        retrieved_at=datetime.now(timezone.utc),
    )
fallback.pyEkstraktor deterministik berbasis regex — jaring pengaman terakhir sebelum manusia
"""Ekstraksi rule-based (tanpa LLM) — jaring pengaman terakhir.

Dipakai hanya bila seluruh rantai LLM gagal (timeout beruntun, provider
down). Karena regex tidak bisa "berhalusinasi" — ia hanya menemukan pola
yang benar-benar tertulis — hasilnya selalu ter-grounding secara
konstruksi, dengan confidence rendah yang jujur (0.4) dan daftar 'needs'
kosong. Laporan tetap bisa terbit; statusnya ditandai fallback.
"""
import re

from schemas import (
    CasualtyReport,
    DisasterEvent,
    DisasterType,
    ExtractionResult,
    SourceDocument,
)

_TYPE_KEYWORDS: list[tuple[DisasterType, tuple[str, ...]]] = [
    (DisasterType.EARTHQUAKE, ("gempa", "tektonik", "magnitudo")),
    (DisasterType.FLOOD, ("banjir", "luapan sungai")),
    (DisasterType.LANDSLIDE, ("longsor", "tanah bergerak")),
    (DisasterType.VOLCANO, ("erupsi", "gunung api", "letusan")),
    (DisasterType.TSUNAMI, ("tsunami",)),
    (DisasterType.WILDFIRE, ("kebakaran hutan", "karhutla")),
    (DisasterType.STORM, ("badai", "angin kencang", "puting beliung")),
]


def _first_int(pattern: str, text: str) -> int:
    m = re.search(pattern, text, re.IGNORECASE)
    if not m:
        return 0
    return int(m.group(1).replace(".", "").replace(",", ""))


def _sentence_around(needle: str, text: str) -> str:
    for sentence in re.split(r"(?<=[.!?])\s+", text):
        if needle.lower() in sentence.lower():
            return sentence.strip()
    return text[:200]


def extract_rule_based(documents: list[SourceDocument]) -> ExtractionResult:
    text = " \n ".join(doc.text for doc in documents)
    low = text.lower()

    disaster_type = DisasterType.OTHER
    for dtype, keywords in _TYPE_KEYWORDS:
        if any(k in low for k in keywords):
            disaster_type = dtype
            break

    deaths = _first_int(r"(\d[\d.]*)\s*(?:orang\s+)?(?:meninggal|tewas)", text)
    injured = _first_int(r"(\d[\d.]*)\s*(?:orang\s+)?luka", text)
    missing = _first_int(r"(\d[\d.]*)\s*(?:orang\s+)?(?:masih\s+)?(?:dalam pencarian|hilang)", text)
    displaced = _first_int(r"(\d[\d.]*)\s*(?:jiwa|orang|kk)?\s*mengungsi", text)
    evac = _first_int(r"(\d[\d.]*)\s*titik pengungsian", text)

    casualties = CasualtyReport(
        deaths=deaths, injured=injured, missing=missing, displaced=displaced,
        evidence_quote=_sentence_around("meninggal", text),
    )

    return ExtractionResult(
        event=DisasterEvent(
            disaster_type=disaster_type,
            title=f"Kejadian {disaster_type.value} (ekstraksi darurat)",
            province="Tidak diketahui",
        ),
        casualties=casualties,
        evacuation_points=evac or None,
        needs=[],
        extraction_confidence=0.4,   # rendah & jujur: hasil regex kasar
        extractor="rule_based_fallback",
        model_used="none",
    )
nodes.pySatu fungsi async per node + fungsi routing murni untuk conditional edges
"""Node-node LangGraph.

Konvensi: setiap node adalah fungsi async murni terhadap state —
membaca field yang ia butuhkan, mengembalikan dict pembaruan parsial.
Fungsi routing (route_*) tidak mengubah state; ia hanya membaca state
dan mengembalikan nama node berikutnya, sehingga mudah di-unit-test.
"""
from datetime import datetime, timezone
from pathlib import Path
from uuid import uuid4

from langgraph.types import interrupt

from config import get_settings
from extractor.workflow import ExtractionFailed, ExtractionWorkflow, make_document
from fallback import extract_rule_based
from resilience import verify_grounding
from schemas import EnrichmentData, ImpactAssessment, SituationReport
from state import AgentState


# --- Ingest ------------------------------------------------------------------

async def ingest_documents(state: AgentState) -> dict:
    documents, errors = [], []
    for source in state["raw_sources"]:
        try:
            if source.startswith(("http://", "https://")):
                # Ambil via HTTP client pilihan Anda; di sini disederhanakan
                # sebagai placeholder fetch teks.
                raise NotImplementedError("fetch URL: gunakan httpx di produksi")
            path = Path(source)
            if path.exists():
                documents.append(make_document(path.name, path.read_text("utf-8")))
            else:  # bukan path & bukan URL => perlakukan sebagai teks mentah
                documents.append(make_document("teks-mentah", source))
        except Exception as exc:
            errors.append(f"ingest gagal untuk {source[:60]}: {exc}")
    if not documents:
        return {"errors": errors + ["Tidak ada dokumen yang berhasil dibaca"],
                "status": "failed"}
    return {"documents": documents, "errors": errors, "status": "ingested"}


# --- Ekstraksi (LlamaIndex di dalam node) ------------------------------------

async def run_extraction(state: AgentState) -> dict:
    settings = get_settings()
    workflow = ExtractionWorkflow(settings=settings, timeout=120, verbose=False)
    feedback = "\n".join(state["validation_errors"]) or None
    try:
        result = await workflow.run(
            documents=state["documents"],
            feedback=feedback,               # mode repair: putaran > 1
        )
        return {"extraction": result, "validation_errors": [],
                "status": "extracted"}
    except ExtractionFailed as exc:
        return {"errors": [f"Ekstraksi LLM gagal total: {exc}"],
                "status": "extracted"}      # extraction tetap None -> routing fallback


async def fallback_extraction(state: AgentState) -> dict:
    result = extract_rule_based(state["documents"])
    return {"extraction": result, "status": "extracted",
            "errors": ["Menggunakan ekstraksi rule-based (LLM tidak tersedia)"]}


# --- Validasi -----------------------------------------------------------------

async def validate_extraction(state: AgentState) -> dict:
    """ExtractionResult sudah tervalidasi Pydantic oleh structured LLM,
    jadi node ini memeriksa kelengkapan operasional + menghitung repair."""
    ext = state["extraction"]
    problems: list[str] = []
    if ext is None:
        problems.append("extraction kosong")
    else:
        if not ext.event.province or ext.event.province == "Tidak diketahui":
            problems.append("field event.province belum terisi dari dokumen")
        if ext.casualties.evidence_quote.strip() == "":
            problems.append("casualties.evidence_quote kosong")
    if problems:
        return {"validation_errors": problems,
                "repair_count": state["repair_count"] + 1,
                "status": "extracted"}
    return {"validation_errors": [], "status": "validated"}


# --- Pengayaan & penilaian ------------------------------------------------------

async def enrich_context(state: AgentState) -> dict:
    """Tempat memanggil tool eksternal (geocoding, API cuaca BMKG, dsb).
    Setiap tool sebaiknya juga dibungkus call_llm_resilient()-style retry
    bila ia memanggil layanan jaringan yang fluktuatif."""
    ext = state["extraction"]
    enrichment = EnrichmentData(
        latitude=ext.event.latitude,
        longitude=ext.event.longitude,
        admin_region=ext.event.province,
        notes=["Geocoding & cuaca: sambungkan provider Anda di node ini"],
    )
    return {"enrichment": enrichment, "status": "enriched"}


async def assess_impact(state: AgentState) -> dict:
    """Penilaian dampak deterministik (bukan LLM) agar skor dapat
    direproduksi dan diaudit: bobot transparan, bukan tebakan model."""
    cas = state["extraction"].casualties
    score = min(100,
                cas.deaths * 4 + cas.missing * 3
                + min(cas.displaced // 100, 25)
                + min(cas.injured // 10, 15))
    level = ("critical" if score >= 80 else "high" if score >= 55
             else "moderate" if score >= 30 else "low")
    assessment = ImpactAssessment(
        severity_level=level,
        impact_score=score,
        affected_population_estimate=cas.displaced + cas.injured + cas.missing,
        rationale=(
            f"Skor {score}/100 dari {cas.deaths} meninggal, {cas.missing} hilang, "
            f"{cas.injured} luka, {cas.displaced} mengungsi (rumus bobot tetap)."
        ),
    )
    return {"assessment": assessment, "status": "assessed"}


# --- Verifikasi grounding -------------------------------------------------------

async def verify_grounding_node(state: AgentState) -> dict:
    report = verify_grounding(state["extraction"], state["documents"])
    settings = get_settings()
    needs_review = report.grounding_rate < settings.min_grounding_rate
    return {"grounding": report, "needs_human_review": needs_review,
            "status": "verified"}


# --- Human review (human-in-the-loop) -------------------------------------------

async def human_review(state: AgentState) -> dict:
    """Graph berhenti di sini (interrupt) dan menunggu operator.
    Operator menerima state ringkas, lalu membalas keputusan:
    {"action": "approve"} / {"action": "reject", "reason": "..."}.
    Eksekusi dilanjutkan lewat Command(resume=...) dari pemanggil."""
    decision = interrupt({
        "reason": "Ekstraksi tidak lolos validasi/verifikasi otomatis",
        "ungrounded_claims": state["grounding"].ungrounded if state["grounding"] else [],
        "validation_errors": state["validation_errors"],
        "extraction": state["extraction"].model_dump() if state["extraction"] else None,
    })
    if decision.get("action") == "approve":
        return {"needs_human_review": False, "status": "verified"}
    return {"errors": [f"Ditolak operator: {decision.get('reason', '-')}"],
            "status": "failed"}


# --- Laporan ---------------------------------------------------------------------

async def generate_report(state: AgentState) -> dict:
    ext, asm, grounding = state["extraction"], state["assessment"], state["grounding"]
    status = ("fallback_extraction" if ext.extractor == "rule_based_fallback"
              else "needs_review" if state["needs_human_review"] else "verified")
    report = SituationReport(
        report_id=f"SITREP-{datetime.now():%Y-%m%d}-{uuid4().hex[:4].upper()}",
        run_id=state["run_id"],
        generated_at=datetime.now(timezone.utc),
        status=status,
        headline=(f"{ext.event.title}: {ext.casualties.deaths} meninggal, "
                  f"{ext.casualties.displaced} mengungsi"),
        event=ext.event,
        casualties=ext.casualties,
        impact=asm,
        grounding=grounding,
        recommended_actions=[
            "Prioritaskan pencarian korban hilang dan kebutuhan logistik pengungsi",
            "Verifikasi ulang angka korban ke posko setempat sebelum publikasi eksternal",
        ],
        sources=state["documents"],
        narrative_summary=(
            f"{ext.event.title} di {ext.event.province}. "
            f"{ext.casualties.deaths} orang meninggal, {ext.casualties.injured} luka-luka, "
            f"{ext.casualties.missing} dalam pencarian, {ext.casualties.displaced} mengungsi. "
            f"Tingkat keparahan: {asm.severity_level} (skor {asm.impact_score}/100). "
            f"Grounding klaim: {grounding.grounded_claims}/{grounding.total_claims} terverifikasi."
        ),
    )
    return {"report": report, "status": "reported"}


# --- Routing (conditional edges) ---------------------------------------------------

def route_after_extraction(state: AgentState) -> str:
    """LLM gagal total (extraction None) -> jaring pengaman rule-based."""
    return "validate" if state["extraction"] is not None else "fallback"


def route_after_validation(state: AgentState) -> str:
    """Ada error & jatah repair masih ada -> kembali ke ekstraksi dengan
    feedback. Jatah habis -> manusia yang memutuskan."""
    settings = get_settings()
    if state["validation_errors"]:
        if state["repair_count"] < settings.max_repairs:
            return "repair"
        return "human_review"
    return "enrich"


def route_after_verify(state: AgentState) -> str:
    """Grounding di bawah ambang -> jangan terbitkan otomatis."""
    return "human_review" if state["needs_human_review"] else "report"
graph.pyPerakitan StateGraph: node, edge lurus, edge kondisional, checkpointer
"""Rakit graph dari nodes.py menjadi executable LangGraph.

Struktur graph persis mengikuti diagram di dokumen arsitektur:
  START -> ingest -> extract -> (fallback?) -> validate
        -> (repair loop | human_review | enrich)
        -> assess -> verify -> (human_review | report) -> END
"""
from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import END, START, StateGraph

import nodes
from state import AgentState


def build_graph(checkpointer=None):
    builder = StateGraph(AgentState)

    # Daftarkan node
    builder.add_node("ingest", nodes.ingest_documents)
    builder.add_node("extract", nodes.run_extraction)
    builder.add_node("fallback", nodes.fallback_extraction)
    builder.add_node("validate", nodes.validate_extraction)
    builder.add_node("enrich", nodes.enrich_context)
    builder.add_node("assess", nodes.assess_impact)
    builder.add_node("verify", nodes.verify_grounding_node)
    builder.add_node("human_review", nodes.human_review)
    builder.add_node("report", nodes.generate_report)

    # Edge lurus
    builder.add_edge(START, "ingest")
    builder.add_edge("ingest", "extract")
    builder.add_edge("fallback", "validate")
    builder.add_edge("enrich", "assess")
    builder.add_edge("assess", "verify")
    builder.add_edge("report", END)

    # Edge kondisional — "{nama_state: node_tujuan}"
    builder.add_conditional_edges(
        "extract", nodes.route_after_extraction,
        {"validate": "validate", "fallback": "fallback"},
    )
    builder.add_conditional_edges(
        "validate", nodes.route_after_validation,
        {"repair": "extract", "human_review": "human_review", "enrich": "enrich"},
    )
    builder.add_conditional_edges(
        "verify", nodes.route_after_verify,
        {"human_review": "human_review", "report": "report"},
    )
    # Hasil review operator: approve -> terbitkan; reject -> selesai (failed)
    builder.add_conditional_edges(
        "human_review",
        lambda s: "report" if s["status"] != "failed" else END,
        {"report": "report", END: END},
    )

    # MemorySaver: state per thread_id tersimpan, run dapat di-resume
    # setelah interrupt human_review. Untuk produksi multi-proses,
    # ganti dengan SqliteSaver / PostgresSaver.
    return builder.compile(checkpointer=checkpointer or MemorySaver())
main.pyEntrypoint: buat state awal, jalankan graph, tangani interrupt, cetak laporan JSON
"""Entrypoint eksekusi.

Contoh:
    python main.py laporan_banjir.txt rilis_bnpb.pdf

Graph di-invoke dengan thread_id = run_id agar checkpointer dapat
melanjutkan run yang sama setelah operator menjawab interrupt.
"""
import asyncio
import sys
from uuid import uuid4

from langgraph.types import Command

from graph import build_graph
from state import initial_state


async def run(raw_sources: list[str]) -> dict:
    run_id = str(uuid4())
    app = build_graph()
    config = {"configurable": {"thread_id": run_id}}

    final_state = await app.ainvoke(
        initial_state(run_id, raw_sources), config=config
    )

    # Graph berhenti di interrupt()? -> tampilkan payload ke operator
    # dan tunggu keputusan (di produksi: kirim ke UI antrian review).
    while "__interrupt__" in final_state:
        payload = final_state["__interrupt__"][0].value
        print("=== HUMAN REVIEW DIPERLUKAN ===")
        print("Alasan:", payload["reason"])
        print("Klaim tak ter-grounding:", payload["ungrounded_claims"])
        answer = input("Setujui laporan? [y/N] ").strip().lower()
        decision = ({"action": "approve"} if answer == "y"
                    else {"action": "reject", "reason": "ditolak operator CLI"})
        final_state = await app.ainvoke(
            Command(resume=decision), config=config
        )

    report = final_state.get("report")
    if report is not None:
        print(report.model_dump_json(indent=2))
    else:
        print("Run selesai tanpa laporan. Status:", final_state["status"])
        print("Errors:", final_state["errors"])
    return final_state


if __name__ == "__main__":
    sources = sys.argv[1:]
    if not sources:
        print("Pemakaian: python main.py <file/URL/teks> [sumber lain...]")
        raise SystemExit(2)
    asyncio.run(run(sources))
06 — STRATEGI RESILIENCE

Retry menangani kegagalan transien; grounding menangani kegagalan kebenaran

Dua kelas kegagalan LLM tidak boleh dicampur. Timeout adalah masalah transport — solusinya mengulang dengan jeda. Halusinasi adalah masalah kebenaran — mengulang panggilan yang sama hanya menghasilkan karangan baru. Arsitektur ini memisahkannya secara eksplisit:

ATimeout berlapis

Timeout ada di dua level: SDK LLM (OpenAI(timeout=30)) dan pembungkus asyncio.wait_for di resilience. Level kedua menangkap kasus SDK menggantung tanpa melempar exception — panggilan dibatalkan paksa, lalu tenacity yang memutuskan lanjut atau berhenti.

BBackoff + jitter, bukan retry membabi buta

wait_exponential_jitter menggandakan jeda setiap percobaan dan mengacaknya. Retry instan beruntun saat provider sedang rate-limit justru memperburuk keadaan dan membakar kuota; jeda acak menyebar beban percobaan ulang.

CRepair dengan umpan balik, bukan pengulangan buta

Saat validasi gagal, yang dikirim ulang bukan prompt yang sama — melainkan prompt + daftar kesalahan spesifik (validation_errors). LLM memperbaiki field yang salah. Batas keras max_repairs = 3 mencegah loop tak berujung yang menghabiskan token.

DGrounding sebagai gerbang penerbitan

Skema Pydantic hanya menjamin bentuk data, bukan kebenarannya — angka korban "999" lolos skema dengan mudah. Karena itu setiap klaim wajib membawa evidence_quote verbatim, dan node verify_grounding adalah gerbang terakhir sebelum laporan terbit.

EDegradasi berjenjang, bukan kegagalan total

Sistem dirancang untuk menurunkan kualitas secara jujur, bukan mati: model cadangan → parser regex → manusia. Setiap penurunan tercatat di state (model_used, extractor, errors[]) dan tercermin di status laporan, sehingga konsumen hilir tahu seberapa besar laporan bisa dipercaya.

FManusia sebagai simpul graph, bukan pengecualian

Kasus yang tidak bisa diputuskan mesin tidak dilempar sebagai exception — ia menjadi node human_review dengan interrupt(). State tersimpan di checkpointer selama menunggu, dan keputusan operator tercatat sebagai bagian dari run yang sama.

Catatan kejujuran batas: verifikasi grounding di sini bersifat leksikal (pencocokan kutipan & angka setelah normalisasi). Ia menangkap halusinasi angka dan klaim karangan — modus kegagalan paling berbahaya pada laporan bencana — tetapi tidak menilai parafrase semantik yang lolos dengan kutipan asli namun konteks keliru. Untuk kebutuhan itu, tambahkan langkah entailment (LLM-judge kedua dengan model berbeda atau model NLI) di node verify_grounding tanpa mengubah struktur graph.

Jalur pengembangan yang lazim

  • Provider LLM lain: ganti impor di extractor/workflow.py (llama-index-llms-anthropic / -ollama) dan sesuaikan daftar exception retryable di resilience.py — graph tidak berubah.
  • Checkpointer produksi: tukar MemorySaver dengan SqliteSaver/PostgresSaver di graph.build_graph(checkpointer=...) agar antrian human review bertahan lintas restart.
  • Tool pengayaan nyata: isi enrich_context dengan geocoding (Nominatim/Places) dan API cuaca BMKG; bungkus panggilan jaringannya dengan pola retry yang sama.
  • Streaming ke dashboard: ganti ainvoke dengan astream_events di main.py untuk menampilkan progres per node secara real-time.

Yang sengaja tidak dilakukan desain ini

  • Bukan sistem pemantauan real-time: graph berjalan per batch dokumen. Untuk feed kontinu, bungkus run() dengan scheduler/queue di luar graph.
  • Penilaian dampak memakai rumus bobot tetap yang transparan — bukan LLM — agar skor antar-kejadian dapat dibandingkan dan diaudit.
  • Angka korban tidak pernah "diperhalus" model: yang tidak ada di dokumen tetap 0/null, dan ketidakpastian ditandai lewat status serta antrian review.
